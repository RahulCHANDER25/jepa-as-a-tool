## Introduction

{/* YOUR WORDS: why this matters, in 3 or 4 sentences. LLMs plan in words but cannot run physics
    in their head; an agent given a world model as a tool can check a move before making it;
    Qian et al. (ACL 2026) found agents rarely use such a tool; ours uses it on every move. */}

Language models reason well in words, but they cannot run physics in their head. Asked to turn a
block by pushing it, an LLM guesses where to push and has no way to check the guess before it
acts. We give it a way to check: a world model, behind one tool call.

<Note>
  Qian et al. (ACL 2026) gave agents a world model as a tool and found they rarely called it. Here
  the agent imagines dozens of pushes for each real one (see Results).
</Note>

## The agent and its world model

Like the agent of _World Models_ (Ha & Schmidhuber, 2018), ours has a part that sees, a part that
predicts and a part that decides. The difference: the part that decides is an LLM, and it uses the
other two through a tool, `simulate(from_frame, plans)`. The tool takes candidate push sequences
and answers with where the objects would end up after each push, as text. Every imagined state
gets an id (`I1`, `I2`, …), so the agent can continue a promising branch later.

<Pipeline />

- **See: V-JEPA 2**, Meta's self-supervised video model, turns a picture of the table into a
  latent: 64 tokens of 1,024 numbers. It stays frozen.
- **Predict: the predictor**, a small transformer we trained, takes a latent and a push and
  predicts the next latent. Chains of pushes stay in latent space.
- **Read: the translator** turns a latent into the state of the table: the T's position and angle,
  or where each ball is. One shared trunk, one small head per world.
- **Decide: Muse Spark** reads that text and picks the next plans to imagine, or a push to make.

The world model never saw the physics engine. It learned only from pictures of random pushes. The
same recipe applies where no simulator exists; here, we can check every imagined frame against the
true physics.

## Lab notebook

Three things that broke on the way, and what they taught us.

- **Balls flying off the table.** At a 4 ms physics step, a contact between two balls lasted
  only two steps, and a ball gained energy at each bounce, until it left the table: a quarter of
  the random pushes. The step is now 2 ms, and the cue withdraws 20 ms after it touches a ball so
  it never pins a ball into a cushion.
- **The EGL crash.** Rendering the 3D worlds on a GPU through EGL failed in two ways on Kaggle:
  with one GPU visible, EGL numbers it 0 whatever its physical index, and an EGL context can only
  be current on one thread at a time, so parallel evaluation workers failed with
  `EGL_BAD_ACCESS`. Every frame is now drawn on one GL thread.
- **Carom tasks that could not be found.** After the cue strike was shortened, a strike carried
  the white ball about 80 px, so from a random start it almost never moved the red one, and the
  task generator ran out of tries. Carom tasks now start with the two balls close together.

## Limits

- **Errors add up over a chain.** The accuracy chart above shows it in every world. The agent
  sometimes notices: _"The last result was weaker than predicted, so I'll try longer pushes to cover
  the distance."_ Here it still runs out of pushes, on a task it solves alone.

<EpisodePlayer run="pusht" episode="pose-0-071__wm_tool__s0">
  A PushT task where the predictions drift and the agent runs out of pushes.
</EpisodePlayer>

- **Near misses.** When an imagined push slides past the T without touching it, the world model
  still moves the T by about 10 px. It saw many clear misses in training, but few pushes that
  graze the T, and those are exactly what a careful agent tries.
- **A new look breaks it** (see above): the translator needs to have seen the scene.

- **Soft tokens.** Today the LLM reads the world model through words. The next step is to give it

  real table filmed by a camera, where V-JEPA 2 was trained.
- **Any agent.** The tool is also served over MCP (`jat mcp`), so other agents can call it.

## Built during the hackathon

Everything in the repository was written between Oct 27 and Nov 4, 2026: the push action on top of
`gym-pusht`, the three MuJoCo worlds, the tasks, the `simulate` tool and agent loop, the data
generator, the V-JEPA 2 encoding, the predictor and translator, the evaluation, the MCP server and
this site. Meta models used: V-JEPA 2 (ViT-L) as the frozen encoder, and Muse Spark as the agent,
through the Meta Model API.

## Appendix

### Reproduce

```bash
uv sync && uv run pytest        # install and test (CPU is enough)
cp .env.example .env            # then set META_API_KEY
uv run jat pipeline --work /tmp/dry --size small --provider dry   # every stage, toy sizes, no GPU
```

The main run is `notebooks/train_and_evaluate.ipynb` (Kaggle, 2 × T4, one session): data, latents,
one translator and one predictor, then the agent alone, with the world model and with the real
physics, in all four worlds.
