## Introduction

Language models reason well in words, but they cannot run physics in their head. Asked to turn a
block by pushing it, an LLM guesses where to push and has no way to check the guess before it
acts. A wrong push cannot be undone, and the next one has to start from wherever the block landed.

We give the agent a way to check: a world model, behind a tool. Before each real push, the agent
can ask "what if I push here?" as many times as it likes, compare the answers, and keep the best
one. The world model learned physics from pictures alone. The LLM brings the language and the
reasoning. Neither is retrained for the other.

## Related work

- **Planning in a world model.** _World Models_ (Ha & Schmidhuber, 2018) and DreamerV3 (Hafner
  et al., 2023) train an agent inside a learned model of its world. LeCun (2022) argues that an
  intelligent agent should plan this way, and V-JEPA 2 (Assran et al., 2025) plans robot-arm
  moves by searching its own latent space. We keep the learned world model, but the one who
  searches it is an LLM, in words.
- **LLMs meet JEPA.** LLM-JEPA (Huang, LeCun & Balestriero, ICLR 2026) adds a JEPA objective to
  the training of an LLM, so the LLM itself learns better embeddings. We take the other road and
  change nothing inside the LLM. The physics lives in a separate world model, trained on
  pictures. The language and the high-level reasoning stay in the LLM. They meet at inference
  time, through tool calls: the world model is a place to try a move before making it.
- **LLMs with a simulator.** Mind's Eye (Liu et al., ICLR 2023) answers physics questions by
  running them in MuJoCo, and RAP (Hao et al., EMNLP 2023) uses the LLM as its own world model
  to plan. Here the simulator is not written by hand: it is learned from pictures, so the same
  recipe can apply where no simulator exists.
- **A world model as a tool.** Qian et al. (ACL 2026) gave agents a world model as a tool and
  found they rarely called it. Ours calls it constantly: about
  <Stat run="pusht" setting="wm_tool" value="imagined" /> imagined pushes per PushT task, for
  <Stat run="pusht" setting="wm_tool" value="pushes" /> real ones.

## The agent and its world model

Like the agent of _World Models_, ours has a part that sees, a part that predicts and a part that
decides. The difference: the part that decides is an LLM, and it uses the other two through tool
calls. It sends the pushes it wants to try and gets back, as text, where the objects would end up.
It can then try more pushes from any imagined state, to plan several moves ahead.

<Pipeline />

1. **See.** V-JEPA 2, Meta's video model, looks at a picture of the table and sums it up as a
   _latent_: 64 tokens of 1,024 numbers each. We use it as it is, frozen.
2. **Predict.** Our predictor, a small transformer, takes a latent and a push and predicts the
   latent after that push. Pushes chain, all in latent space: imagining needs no image at all.
3. **Read.** Our translator turns any latent, real or imagined, into numbers the LLM can use:
   where the T is and how it is turned, or where each ball is. One shared trunk, one small head
   per world.
4. **Decide.** Muse Spark reads those numbers, then asks to imagine more pushes, or makes a
   real one.

The world model never saw the physics engine: it learned only by watching pictures of random
pushes. The same recipe applies where no simulator exists. Here we do have one, so we can check
every imagined state against the true physics.

## How far ahead can it imagine?

How far off is the world model? The chart counts the imagined states that land within 20 px (and
15° for the T) of where the real physics puts them. The longer the chain of imagined pushes, the
more the errors add up. After four pushes in a row, most imagined states are still right on PushT
and on the tabletop, the two worlds where the world model helps. On billiards, where balls roll
fast and collide, most are already wrong.

## A wrong world model is worse than none

The fourth world has the tabletop's physics, but a new look: another table, another light, another
color, and the camera moved. The world model never saw it. It misreads the picture before any
imagined push (only 9% of the real frames are read within 20 px), and then tells the agent confident, wrong positions. The agent trusts the tool.
Alone, it solves <Stat run="tabletop-new-look" setting="no_tool" /> of the tasks there. With the
world model, only <Stat run="tabletop-new-look" setting="wm_tool" />.

<ResultsChart runs={["tabletop", "tabletop-new-look"]}>
  The same physics, two looks. On the look it was trained on, the world model helps. In the new
  room it misleads the agent.
</ResultsChart>

This is also the most useful result of the project, because it says exactly what to improve. The
agent side is ready: with a perfect world model it solves almost every task. What limits it is
how well the world model imagines, and a world model gets better with more and more varied data.

## Limits

- **Errors add up over a chain.** Plans of three or four pushes drift, and the agent sometimes
  runs out of pushes on a task it solves alone.
- **Near misses.** When an imagined push slides past the T without touching it, the world model
  still moves the T by about 10 px. It saw many clear misses in training, but few pushes that
  graze the T, and those are exactly what a careful agent tries.
- **A new look breaks it** (above): the translator needs to have seen the scene.

## What comes next

- **More worlds and more looks.** Train the world model on many rooms, tables and lights, so a
  new room is no longer new.
- **Real cameras.** The world model learns from pictures alone, so the same recipe applies to a
  real table filmed by a camera, where V-JEPA 2 was trained.
- **Soft tokens.** Today the LLM reads the world model through words. Next, give it the latent
  directly, as tokens it learns to read.
- **Any agent.** The world model is public on
  [Hugging Face](https://huggingface.co/racoon25/jepa-as-a-tool), and served over MCP
  (`jat mcp`), so any agent can imagine before it acts.

An LLM brings the words and the reasoning. A world model brings the physics. Put together, the
agent does what people do before a move that cannot be undone: it imagines first.

## Built during the hackathon

Everything in the repository was written between Oct 27 and Nov 4, 2026: the push action on top of
`gym-pusht`, the three MuJoCo worlds, the tasks, the world-model tool and agent loop, the data
generator, the V-JEPA 2 encoding, the predictor and translator, the evaluation, the MCP server and
this site. Meta models used: V-JEPA 2 (ViT-L) as the frozen encoder, and Muse Spark as the agent,
through the Meta Model API.

### Reproduce

```bash
uv sync && uv run pytest        # install and test (CPU is enough)
cp .env.example .env            # then set META_API_KEY
uv run jat pipeline --work /tmp/dry --size small --provider dry   # every stage, toy sizes, no GPU
```

The main run is `notebooks/train_and_evaluate.ipynb` (Kaggle, 2 × T4, one session): data, latents,
one translator and one predictor, then the agent alone, with the world model and with the real
physics, in all four worlds.
